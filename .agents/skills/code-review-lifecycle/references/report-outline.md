# 审查报告骨架

报告是本次审查**唯一允许新增**的仓库文件。文件名按用户口径（`CODE_REVIEW_YYYY-MM-DD.md`，重名追加 `_2`/`_3`）；目录跟随仓库既有约定（如 `docs/worklog/`），并在首行说明放置理由。

下面每一节都标了「为什么不能省」。被省略的通常是 §7.2、§7.3、§8.3、§9 与附录 A——恰好是读者复核时要用的四块。

## 写作纪律

- **每条都要能被反驳**：给位置、给命令、给期望值。写不出判据的结论降级或删掉。
- **区分「没做」与「没问题」**：未覆盖的部分写进附录 A，不要用「未发现」冒充「不存在」。
- **不要复述仓库自述**：报告的价值在实测差异，不在抄 AGENTS.md。
- **同族合并**：一条里给计数 + 全部文件 + 3~5 个代表位置；逐条罗列 20 个同型问题等于没分析。
- **度量必须带阈值**：超长函数按多少行、嵌套按几层、形参按几个，全部写进 §2.2。同一仓库换阈值会得出不同计数，不写阈值的「25 个超长函数」不可复现。
- **处置状态回写**：审查后如果用户让你继续修复，改的是报告里的「处置状态」列，不是把原结论删掉。
