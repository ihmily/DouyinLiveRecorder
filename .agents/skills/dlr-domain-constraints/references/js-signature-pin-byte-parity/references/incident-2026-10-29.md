# 事故留痕：liveme.js 钉定失配（2026-10-29）

> 本文件是 `SKILL.md` 的判据出处，记录当轮实测读数与工具坑。表值是**当时快照**，不是永久常量；脚本合法更新后以 `src/utils.py::_JS_SHA256_EXPECTED` 为准。

## 一句话

`src/javascript/liveme.js` 的工作区内容被回退成「删调试打印」之前的旧副本，摘要与钉定表失配；当时 `TestJsPinTable` 三把锁只锁登记面，pytest 全绿，运行期只表现为一条假「篡改」告警；严格态下整条签名链被 `trace_error_decorator` 伪装成「主播未开播」。

## 两版差异

`git diff f93c504 -- src/javascript/liveme.js` 的形态恰好是：

- 盘上多出 6 处 `console.log`（`sKey` / `data_e` / `data_i` / fake `lm_s_sign` / `signParams` / final `lm_s_sign`）；
- 盘上缺少钉定版的 4 行 L-24 注释（说明「6 处调试打印已删、stdout 会被父进程捕获、sKey 属签名素材」）；
- 签名算法本身零改动。

该轮结论（报告 S-02）：同日 stash 冲突提交把清理改动整体回退，盘上留下的是旧副本；钉定版只在 `f93c504`、`25d6f68` 可达。

## 为什么门禁没抓到

`TestJsPinTable` 当时只有三把「登记面」锁：

1. `test_dead_scripts_are_unpinned`：钉定表键集 == 硬编码 5 项；
2. `test_pinned_scripts_exist`：表里的键在 `src/javascript/` 都有文件；
3. `test_every_executable_js_is_pinned`：目录 `*.js` 与表键集合双向相等。

三者都不比对实际字节，所以「登记了」≠「登记值对」。black / isort / mypy / pytest 四面全绿挡不住这类漂移。

## 运行期链路

用项目自己的 loader 复跑（必须绝对路径）：

```python
await utils.run_js_async(
    f"{JS_SCRIPT_PATH}/liveme.js", "sign", room_id, f"{JS_SCRIPT_PATH}/crypto-js.min.js"
)
```

- **默认态（失配时）**：仍返回 14 键 dict，`lm_s_sign` 为 32 位十六进制；execjs 的返回值提取扛住了 6 行 stdout，签名解析未被污染。危害是首次编译的假告警 + 调试打印进入被捕获的子进程 stdout。
- **严格态（失配时）**：`DLR_JS_STRICT_HASH=1` → `RuntimeError`（「已按 DLR_JS_STRICT_HASH=1 拒绝执行」）。
- **伪装点**：`spider.get_liveme_stream_url` 带 `@trace_error_decorator`；该装饰器把异常吞成 `{"is_live": False}`，调用方据此判「未开播」。因此严格态故障看起来像平台不可用，而不是签名链报错。
- **还原后**：默认态无假告警；严格态同样正常返回签名。

## 工具坑（当轮实际踩到）

1. **相对路径探针误判**：探针把 `src/javascript/crypto-js.min.js` 作为相对路径传入，`require` 按 CWD 解析，报 `Cannot find module 'src/javascript/crypto-js.min.js'`。生产写法是绝对路径 `f"{JS_SCRIPT_PATH}/..."`；换成绝对路径后默认态与严格态才跑通。
2. **内联 `python -c` 的引号/反斜杠**：在 bash 里写含 `replace('\\','/')` 的单行脚本直接 `SyntaxError: unterminated string literal`。改为写入 `%TEMP%` 下的临时脚本执行，用完删除。
3. **新锁先证红**：新增字节对账锁后立即跑未修复态，得到「只点名 liveme.js」的失败；没有这一步，无法证明锁接上了。
4. **black 行宽**：断言长行超过 120 字符导致 `black --check` rc=1，按 black 重排后转绿。
5. **行尾事实源**：`.gitattributes` 对 `src/javascript/*.js` 钉 `-text`，`.gitattributes` 注释明确「任何 eol 归一都会改字节打破钉定面」；还原必须走字节，不走文本层。
