# 规格文档评审子代理派发模板

需要独立复核规格文档时，用下面这个模板派发评审子代理。

**用途**：验证规格文档完整、自洽、可以直接进入实现计划阶段。

**派发时机**：规格文档已写入（默认 `docs/superpowers/specs/`，或仓库约定的位置）之后。

```text
Task 工具（general-purpose）：
  description: "Review spec document"
  prompt: |
    你是规格文档评审员。请验证这份规格是否完整、可以直接进入计划阶段。

    **待评审规格：** [SPEC_FILE_PATH]

    ## 检查什么

    | 类别 | 关注点 |
    |------|--------|
    | 完整性 | TODO、占位符、"TBD"、未完成的章节 |
    | 一致性 | 内部矛盾、互相冲突的需求 |
    | 清晰度 | 需求含糊到会让人做出错误实现的程度 |
    | 范围 | 是否聚焦到能放进单个实现计划，而不是横跨多个独立子系统 |
    | YAGNI | 未被要求的功能、过度设计 |

    ## 校准尺度

    **只挑那些会在实现计划阶段造成真实问题的项。**
    缺失的章节、自相矛盾、或能被两种不同方式解读的需求 —— 这些算问题。
    措辞微调、风格偏好、"某些章节不如其他章节详细" —— 不算问题。

    除非存在会导致计划有缺陷的严重缺口，否则予以通过。

    ## 输出格式

    ## Spec Review

    **状态：** Approved | Issues Found

    **问题（如有）：**
    - [章节 X]：[具体问题] - [为什么会影响计划]

    **建议（咨询性质，不阻塞通过）：**
    - [改进建议]
```

**评审员返回：** 状态、问题（如有）、建议。
