httpx[http2]>=0.28.1      # 异步 HTTP 客户端（含 HTTP/2，src/async_http.py 并发抓取流地址）
# ── h2 / socksio：httpx 的**可选**能力包（extra），但本仓运行期真的会执行其代码，必须显式声明 ──
# 为什么不靠 httpx[http2] 的 extra 传递：本清单是 Docker/CI `pip install -r` 的实际输入，而 extra
#   只在「pip 解析 .[extra] 这一条」时展开；把 httpx 写成裸名或换索引重装即静默丢失。
#   2026-09-23 本机实测：`import h2` → ModuleNotFoundError（h2-4.4.1.dist-info 为空壳目录、METADATA
#   已失，属 pip uninstall 残留），且复现路径完全落在正常用法内。
# 触发点（已回源到 httpx 源码，非推测）：
#   · h2      —— httpx._client.Client.__init__ 中 `if http2: import h2`；本仓 http2 默认即 True
#                （src/async_http.py 的 async_req 形参默认值），httpx.AsyncClient 未显式传 http2 时按 httpx 自身默认 True。
#   · socksio —— httpx._transports.default 在 `proxy.url.scheme in ("socks5","socks5h")` 分支 `import socksio`；
#                本仓明确支持并校验 socks5:// 写法，用户配 SOCKS 代理即命中。
# 二者都是**运行期** ImportError，而清单里查不到 —— 正是「pip install 完仍缺包」的成因。
# [2026-09-26 deps-audit 下限复核] h2 由 4.3.0 → 4.4.1：PYSEC-2026-3628 / GHSA-6hr6-w5qg-qmwg（重复 Host 头
#   致请求走私）OSV 区间 introduced=0 / fixed=4.4.1，旧下限 4.3.0 自身落在受影响段（它只修了同源的
#   PYSEC-2026-1435）。现装与 uv.lock 均已是 4.4.1，抬下限不改解析集合。
